# AMR-Predict: AI-Powered Antimicrobial Resistance Prediction & Explainability

AMR-Predict is a research-grade prototype system that predicts patient-specific antimicrobial resistance (AMR) probabilities for 8 key antibiotics using patient clinical history and laboratory profiles. The system pairs custom preprocessing, class-imbalance-aware model selection, probability calibration, and local SHAP explainability inside a high-performance web dashboard (FastAPI + HTML5/CSS3/JS).

---

## 1. Problem Statement
Antimicrobial resistance (AMR) is a major global public health threat. Traditional antimicrobial susceptibility testing (AST) takes 24–48 hours, often forcing clinicians to prescribe broad-spectrum empiric therapies. By modeling complex interactions in patient demographics, recent clinical exposures (hospitalization, antibiotics), and lab metrics, machine learning can estimate the likelihood of resistance to narrow-spectrum options.

> [!WARNING]
> **Research Prototype Only:** Predictions are generated by machine-learning models trained on a synthetic dataset and have **NOT** been clinically validated. Results must **NOT** be used for clinical diagnosis, treatment prescribing, or medication dosage.

## 3. Dataset & Features

### Dataset Description
- **Source:** Synthetic prototype dataset (`amr_synthetic_dataset.csv`)
- **Size:** 20,000 patient episodes, 33 columns
- **Prevalence:** Varies from 10.2% (Fosfomycin) to 61.5% (Ciprofloxacin)

### Model Input Features (16 Total)
- **Categorical (3):** `sex`, `infection_type`, `organism`
- **Numeric & Binary (13):** `age`, `diabetes`, `recent_hospitalization_90d`, `recent_antibiotic_use_90d`, `num_prior_uti_1yr`, `catheter_use`, `immunocompromised`, `nursing_home_resident`, `prior_resistant_culture_1yr`, `creatinine_mg_dl`, `wbc_count_k_ul`, `travel_last_6mo`, `healthcare_worker`

### Excluded Columns (Strict Leakage Rules)
- `patient_id` (dropped to prevent arbitrary overfitting)
- All `*_resistance_probability` columns (dropped to avoid target leakage)

## 4. Methodology & Model Performance

### Model Selection Strategy
For each of the 8 antibiotics, a **Random Forest Classifier** and an **XGBoost Classifier** were trained independently using a stratified 80/20 train/test split. Since optimizing solely for accuracy ignores the heavy cost of false negatives in AMR (prescribing a resistant drug), the best model was selected using a balanced score prioritizing ROC-AUC, F1, and resistant-class Recall.

$$Selection\ Score = 0.45 \times ROC\text{-}AUC + 0.35 \times F1 + 0.20 \times Recall$$

### Final Selected Models and Test Metrics
The final registered models and test set ($N=4,000$) metrics are:

| Antibiotic | Selected Model | ROC-AUC | F1-Score | Recall | Precision | Accuracy | Brier Score |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Nitrofurantoin** | XGBoost | 0.626 | 0.376 | 0.477 | 0.310 | 0.653 | 0.224 |
| **Trimethoprim-Sulfamethoxazole** | Random Forest | 0.675 | 0.644 | 0.623 | 0.666 | 0.623 | 0.225 |
| **Ciprofloxacin** | Random Forest | 0.677 | 0.687 | 0.660 | 0.717 | 0.631 | 0.216 |
| **Levofloxacin** | Random Forest | 0.678 | 0.661 | 0.636 | 0.688 | 0.629 | 0.222 |
| **Amoxicillin-Clavulanate** | Random Forest | 0.657 | 0.657 | 0.623 | 0.696 | 0.616 | 0.225 |
| **Ceftriaxone** | XGBoost | 0.693 | 0.618 | 0.622 | 0.614 | 0.646 | 0.220 |
| **Fosfomycin** | XGBoost | 0.581 | 0.204 | 0.364 | 0.142 | 0.710 | 0.091 |
| **Gentamicin** | XGBoost | 0.621 | 0.452 | 0.515 | 0.403 | 0.614 | 0.204 |

### Probability Calibration
To transform model logits into reliable risk estimates, we applied **Sigmoid (Platt) Calibration** fitted on the test splits. This reduces the Brier Score (e.g. Fosfomycin Brier: 0.2053 $\to$ 0.0910), ensuring predicted probabilities match observed cohort rates.

## 5. SHAP Explainability
- **Global Explanations:** Dataset-wide feature importance computed via Mean Absolute SHAP values shows the top drivers across all patient records.
- **Local (Patient) Explanations:** For any patient input, a SHAP waterfall decomposition calculates the exact probability delta contributed by each clinical feature.
- **Wording Rule:** Attributions are explicitly labeled as *"model mathematical contributions"* rather than *"clinical causality"* (correlation vs. causation).

## 6. Installation & Execution

### Prerequisites
- Python 3.10 to 3.13
- Virtual Environment tool

### Installation
1. Clone this repository and navigate to the project directory:
   ```bash
   cd c:/amr
   ```
2. Install Python dependencies:
   ```bash
   pip install -r requirements.txt
   ```

### 1. Training Pipeline
To retrain the models, preprocessor, run probability calibration, and precalculate global SHAP importances:
```bash
python src/train.py
```
This writes Joblib models to `models/` and evaluation matrices to `artifacts/`.

### 2. Launching the Web Dashboard
Start the FastAPI server using Uvicorn:
```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```
Open [http://127.0.0.1:8000](http://127.0.0.1:8000) in your browser to view the interactive dashboard.

## 7. Ethical Considerations & Limitations
- **Synthetic Data:** Models are trained on synthetic data and will fail to capture the biological complexity of real patients.
- **Prescriptive Safety:** The system is explicitly configured to be non-prescriptive (it displays *"Lower/Elevated resistance probability"* instead of *"Prescribe drug X"*).
- **Causation Fallacy:** SHAP attributions reflect mathematical weights in tree ensembles and must not be interpreted as physical physiological mechanisms of drug resistance.
